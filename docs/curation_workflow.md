# 先验证据整理与复核

## 1. 明确问题和来源范围

先记录用途、物种、检索式、日期、来源版本及纳入/排除理由。保留已克隆功能基因、自然变异与关联候选；文献库的收录不以特定群体芯片覆盖、等位频率、亲本是否携带或关联显著为条件。已克隆基因即使尚无已知有利自然等位，也可以作为基因功能先验保留。未知坐标和未定位身份不必从来源台账中删除。

现有项目排除孕穗期耐冷数据及其派生证据。检索命中需要按具体来源人工确认该范围；代码不以一个 `cold` 关键词自动裁决整篇文章。其他项目应明确自己的研究范围。

## 2. 来源与命题

一个来源可涉及多个基因和实验，一个实验可报告多个端点。来源 DOI、实验、事件、材料与比较、端点分别建立标识；不要将多个性状或同一数据的不同表示计作独立验证。来源、版本、可访问状态、内容哈希、权利与正文/图表定位分别记录。已读未报告、未获取、未核实、冲突与排除不能相互替代。

最低证据链为：

`基因 → 事件或未定原因 → 材料/对照 → 条件与实验 → 性状/效应/代价 → 来源及页、图或表定位 → 审阅和复核状态`

原文结论、作者解释与整理者推断要分开。材料背景和环境可能改变效应；产量构成性状、单株产量及小区实收产量应保持区别。负结果、反向结果与冲突继续保留；“差异不显著”不能自动写成“无代价”或“等效”。

## 3. 事件与证据等级

- 自然事件、人工诱变/构建及关联代理分开；基因功能、整段近等基因系或单倍型作用不能自动分配给单个 SNP。
- 原始和规范化表示分别记录。坐标至少核对参考组装、染色体、坐标体系、链方向及 REF/ALT；不明时留空并在 `notes` 中说明。本仓库不做坐标转换或参考碱基核验。
- `event_causal`、`allele_supported`、`association_only`、`molecular_functional`、`gene_functional`、`unresolved` 是**整理者对特定端点的判断**，不是程序自动打分。同一事件对分子端点和田间产量端点可有不同证据等级。
- `same_event`、`distinct_event`、`component_of`、`duplicate_representation` 与 `unresolved` 关系分开。只有具体证据支持时才判断同一事件；同名、同 DOI、相同缺失长度或相同基因不足以自动合并。

## 4. 增量复核与发布

先查来源版本、已有命题及已审范围。新增问题以“来源哈希、基因/事件、端点、比较、缺失字段、裁决版本”固定任务；原文已报告但未提取、原文未报告、尚未读和冲突分别处理。科学增量由独立复核者依据原始证据复核；格式变化仅作来源、字段和导出一致性检查。

每版固定输入与脚本哈希，保存预期及实际记录数、失败/未决清单、独立复核范围及新旧版本关系。新版本写入新目录。当前程序检查结构关系和哈希，并记录**输入中填写**的审阅状态；它不验证原文、第三方权限、独立复核者身份、回执或科研判断。发布科学结论之前仍需人核对这些内容。

## 5. 下游使用

文献先验、关联、投影分型及实验直接分型是不同证据。不同项目的材料身份、分型来源、家系结构和环境需要独立核验；variant-only VCF 中的缺失记录不是参考型。先验与目标群体数据连接后，应事先固定比较、端点及多重校正，并保留不利、固定或不可估计的结果。证据表本身不提供材料在任何特定背景中的实测增益。
